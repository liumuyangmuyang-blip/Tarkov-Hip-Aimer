# 取消开镜后保持瞄准点显隐正确

Status: ready-for-agent
Resolution: completed

## 问题说明

玩家使用点一下切换开镜。开镜时按 Tab 打开背包，游戏已退出开镜，工具却仍记着开镜。
关闭背包后瞄准点仍隐藏，再按右键开镜时反而显示，此后一直相反。
背包里的右键物品操作同样会改变工具记录；Esc 退出也没有对齐记录。

已用实际输入到显隐计算的源码链路连续离线复现三次。游戏侧 Tab 强制关镜的行为来自用户描述，尚未进行游戏内验证。

## 解决方式

增加可配置的取消开镜键，默认包含 Tab、Esc。
在点一下切换模式下，任一取消键被按下时，将工具记录的开镜状态清为未开镜。
不判断是否在背包内；取消键在现有允许读取实时按键的场景中始终具有这一含义。

背包中无论右键多少次，只要最终通过配置的取消键退出，退出后的瞄准点就应回到未开镜的显示状态，下一次开镜正常隐藏。
本次不单独控制背包内瞄准点的显隐。

## 用户场景

1. 作为使用点一下切换的玩家，我希望开镜后用 Tab 打开并关闭背包，退出后瞄准点正常显示，避免显隐反转。
2. 作为玩家，我希望关闭背包后再次开镜时瞄准点隐藏，之后反复开关镜都保持正确。
3. 作为玩家，我希望背包里不点右键时，通过 Tab 或 Esc 退出都能恢复正确显示。
4. 作为玩家，我希望背包里右键一次或多次后，通过 Tab 退出仍能正确显示。
5. 作为玩家，我希望背包里右键一次或多次后，通过 Esc 退出仍能正确显示。
6. 作为玩家，我希望连续按取消键时，工具始终记录为未开镜，不会再次翻转。
7. 作为玩家，我希望取消键和开镜键在同一帧被按下时，以取消开镜为准。
8. 作为改过游戏按键的玩家，我希望能配置多个取消开镜键，适应自己的操作习惯。
9. 作为玩家，我希望保存并重启后仍使用自己设置的取消开镜键。
10. 作为升级工具的玩家，我希望没有新配置项的旧设置仍可使用，并自动获得 Tab、Esc 的默认规则。
11. 作为使用按住开镜的玩家，我希望这次修复保持按住和松开时的原有显示行为。
12. 作为玩家，我希望取消开镜只对齐开镜记录，不改变换手、强化准星和其他运动状态。
13. 作为玩家，我希望切到其他窗口或在工具设置里操作时，仍遵守现有的实时按键读取限制。
14. 作为玩家，我希望知道取消开镜键只修正工具记录，不会向游戏发送关镜操作。

## 实现约定

- 修改输入采集、开镜状态跟踪和按键设置，沿用现有按键查询方式。
- 取消开镜键支持多个，默认 Tab、Esc；支持修改和保存，旧配置缺少该项时使用默认值。
- 取消开镜是清零操作，不是开关翻转；以按下事件触发，同一帧优先于开镜翻转。
- 取消时正确更新按键历史，避免仍按住的开镜键在下一帧又被误认为新按下。
- 本次只改变点一下切换模式下的开镜跟踪，按住开镜模式保持原有行为。
- 不调用整个运动引擎的重置来取消开镜，保留换手、强化准星、移动和其他已有状态。
- 不新增背包打开状态，不根据 Tab 的次数猜测菜单是否打开。
- 取消输入遵守现有实时按键读取条件，不绕过窗口前台限制，也不影响预览原有行为。
- 设置说明明确默认按键、清零含义和适用范围，避免让玩家以为工具会控制游戏。
- 新增逻辑按函数和文件限制拆分，避免继续扩大已有超长文件和函数；不做与修复无关的大范围整理。

## 测试约定

- 用户已认可的主要测试入口为真实“读取按键 → 实时输入处理 → 显隐计算”链路，替代物理按键查询，不启动游戏或叠加窗口。
- 断言退出背包后的实际显隐，以及再次开镜和关镜后的显隐；不只检查某个内部布尔变量。
- 覆盖 Tab 进入后分别用 Tab、Esc 退出，背包中右键次数至少包括 0、1、2、3 次，区分奇偶情况。
- 覆盖重复取消、取消与开镜同帧、取消时开镜键仍按住、松开后再次开镜。
- 覆盖取消键改为其他键、多个取消键、配置保存读取、旧配置补默认值；移除默认键后应遵守新配置。
- 验证按住开镜、换手、强化准星及现有前台读取限制不受影响。
- 仓库目前没有独立测试项目。核实阶段已经通过内存编译实际源码建立快速离线复现，可优先沿用并整理为可重复执行的回归入口。
- 使用项目既有的 .NET Framework 构建方式做编译验证；不把离线测试或编译通过称为实机验证。
- 实施后列出游戏内验收步骤。没有获得游戏操作授权时，不自行进行实机操作。

## 不在本次范围

- 背包内始终隐藏瞄准点，或背包内忽略所有右键输入。
- 识别背包、物品右键菜单、确认窗口等界面的实际打开或关闭状态。
- 没有按任何配置取消键的其他退出方式，例如点击界面关闭按钮。
- 用截图、图像识别或读取游戏内存确认实际开镜状态。
- 修改按住开镜方式、全局输入机制、运动计算或其他外观功能。

## 补充说明

默认取消键按下时总会清零，而不是只在背包退出时清零；用户已明确认可这个范围。
玩家应配置与自己游戏操作匹配的取消键；工具不会知道游戏是否真正完成了关镜。
